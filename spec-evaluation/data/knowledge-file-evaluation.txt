  Verdict: several real mismatches

  The big-picture story is consistent (canvas-based, perf-focused, log/symlog, ID-keyed Path2D cache, zero deps, ESM-only), but several answers contradict the README — some are notable.

  Significant mismatches

  1. NaN rendering (user answer) — Q "How should NaN and ±Infinity values be visually represented?"
  - Knowledge: "NaN breaks the line (gap in the series)."
  - README:1325-1328 "Skip missing points and connect across — the line continues through the neighbors of the gap."
  - These are opposites.

  2. Crosshair / zoom-rect location (prepared) — "Canvas stack" Q

  - README:1246 and task brief explicitly say crosshair/zoom-rect live in the DOM overlay, not on canvas. (Tip: README explicitly lists "crosshair or zoom rectangle" as the canonical DOM elements.)

  3. Path2D coordinate space (prepared) — "Path2D cached in zoom-normalized coords" Q
  - Knowledge: "Path2D objects are built once in data-space coordinates (raw x/y values)."
  - README:1239-1241 (and task brief) say paths are stored in zoom-normalized data coords, bound to the configured window/zoom, with re-normalization only on large zoom changes. The "normalized" part is the whole
  point; raw data-space contradicts it.
  
  4. Y-axis zoom (prepared) — "Zoom state format" Q
  - Knowledge: "{ xMin, xMax } — X-axis only. Y always auto-scales."
